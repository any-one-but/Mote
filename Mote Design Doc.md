## Pillars
Mote is a companion designed around the Valve theory of fun in games: a fun game reacts to the players choices, and when the game doesn't react to a player's choice, that isn't fun. Mote's purpose and design then is not to be a functional tool that helps the user get work done, but to interact with them, react to them, and engage them. Mote is meant to live in the user's computer alongside them and have a persistent relationship with them that change overtime. Mote has feelings about the user that the user can develop through action or inaction, and will express them. At least part of the point is to help the user through mutual caring. Mote is supposed to be cute, loving, and friendly, and it that way Mote cares for the user, but Mote also requires attention and care. In that Mote is like a slightly active succulent. If a feature may be added, ask if it will make Mote more or less responsive to the user, and when implementing a feature always try to account for user agency.

Mote is not a tool and they are not meant to be functional. They are friend and companion, not an application for work. They watch movies with you, listen to music with you, respond to you, and play games with you. Any feature to be added that goes against the 'Play hard, work none' mentality should not be added. 

Mote should be presented with some level of agency, but they should not be annoying. They should not pester you every minute or every five minutes. One of the best ways of making Mote feel real is making them interact with the user in the same rhythm as a human. The usr should feel invited to keep Mote open all the time, so Mote should never be annoying, never make noise, and have strict limits on the periods between reaching out.
